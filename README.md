# AI Assignment Review Action

Публикуемый composite GitHub Action: оценивает **diff pull request** по Markdown-критериям из базовой версии репозитория и обращается к API с OpenAI-совместимым интерфейсом (по умолчанию — Kodik Router).

Action не делает checkout и не запускает код ученика. Diff и rubric получает только GET-запросами к GitHub API. Оценка появляется в GitHub Actions Summary; PR автоматически не комментируется. Если модель считает задание невыполненным или балл ниже порога, шаг завершается с ошибкой.

## Подключение

1. Опубликуйте содержимое этой папки в отдельном GitHub-репозитории Action.
2. Создайте в учебном репозитории секрет `KODIK_API_KEY` с ключом провайдера.
3. Добавьте rubric, например `.github/assignment-rubric.md`. Файл берётся из **base commit PR**, а не из изменений ученика.
4. Добавьте workflow из [`examples/workflow.yml`](examples/workflow.yml), заменив `OWNER/ai-assignment-review` на адрес Action и указав commit SHA релиза вместо тега `@v1`.

Пример rubric: [`examples/rubric.md`](examples/rubric.md).

## Безопасность PR из форков

Workflow использует `pull_request_target`, чтобы иметь доступ к API-ключу и читать diff PR из форка. Это чувствительный триггер. Пример намеренно **не** использует `actions/checkout` и не запускает скрипты из PR. Не добавляйте в этот workflow checkout `head` PR, установку зависимостей из PR или выполнение кода ученика. Необходимы только права `contents: read` и `pull-requests: read`.

Закрепляйте Action и внешние Actions по полному неизменяемому commit SHA, а не по изменяемым тегам. Владелец репозитория должен доверять коду Action, которому передаётся API-ключ. Учтите, что diff задания отправляется выбранному AI-провайдеру; не используйте такой режим для репозиториев с данными, которые нельзя передавать этому провайдеру.

Если используете обычный `pull_request`, секреты недоступны workflow для PR из форка, поэтому AI-проверка не сможет вызвать API. Не переключайте триггер на `pull_request_target`, пока не соблюдены меры безопасности выше.

## Входы

| Вход | Обязательный | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `api-key` | Да | — | Ключ OpenAI-совместимого API; передавайте через GitHub Secret. |
| `github-token` | Да | — | Токен для чтения PR и rubric. Нужны только `contents: read` и `pull-requests: read`. |
| `rubric-path` | Да | — | Путь к MD-файлу критериев относительно корня репозитория. |
| `model` | Нет | `qwen/qwen3.8-27b:free` | Идентификатор модели провайдера. |
| `base-url` | Нет | `https://api.kodikrouter.ru/v1` | Базовый URL OpenAI-совместимого API. |
| `passing-score` | Нет | `70` | Минимальный балл от 0 до 100. |
| `max-diff-chars` | Нет | `50000` | Максимальный размер rubric и сериализованного diff. При превышении Action прекращает проверку и не усекает данные. Минимум — 1000. |
| `pull-request-number` | Нет | Из event payload | Номер PR; можно задать вручную при `workflow_dispatch`. |

Action ожидает Python 3.10+ на runner. В примере Python устанавливается через `actions/setup-python`.

## Результаты

- `score` — балл от 0 до 100;
- `passed` — `true`, только если модель отметила работу как выполненную **и** балл не ниже `passing-score`;
- `summary` — Markdown-сводка.

Сводка также добавляется в GitHub Actions Summary. Невалидный ответ модели, недоступный rubric, отсутствующий текстовый patch или превышение лимита приводят к ошибке вместо фиктивной оценки. Провайдер модели должен поддерживать Chat Completions и `response_format: {"type":"json_object"}`.

GitHub API может не вернуть patch для бинарных или очень больших файлов — в этом случае Action завершится ошибкой. GitHub также может сократить очень большие patch-и без явного признака усечения; это ограничение API Action надёжно обнаружить не может. Для таких PR используйте изменения, разбитые на меньшие текстовые части. Оценка делается только по diff, тесты и код не запускаются.
